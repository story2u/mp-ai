# WeChat Outline Planner - Agent Memory

## Content Type Patterns

### Installation/Tutorial Articles
- **Best structure**: "What is it - Prerequisites - Step-by-step methods - Configuration - Troubleshooting"
- **Key insight**: Readers need both "why should I care" (chapters 1) AND "how do I do it" (chapters 3-4), with preparation (chapter 2) as the bridge
- **Comparison tables work well** for multiple installation methods (difficulty/audience/pros/cons)
- **Troubleshooting section is essential** for installation guides -- use "Symptom - Cause - Solution" three-part format
- **Security warnings should be woven throughout**, not isolated in one section

### Headline Formulas for Tutorial Content
- "[Number] + method/way + action verb" pattern works for tutorials (e.g., "four methods to build your AI assistant")
- Star count / popularity metrics create credibility hooks (e.g., "200K Star AI tool")
- "Your [thing] is ready" pattern creates anticipation

### Opening Hooks
- **Daily scenario hook**: Describe a relatable moment where the tool solves a real problem, then reveal the tool
- **Gap hook**: "You've heard of X but never tried it -- the real barrier is Y"
- Works well to combine both: scenario first, then identify the gap this article fills

## Structural Notes
- 5 chapters is the sweet spot for installation tutorials (concept + prep + install + config + troubleshooting)
- Total word count target: 3000-3500 for tutorial articles
- Core chapter (the actual installation steps) should get 600-800 words, roughly 2x other chapters
- Every chapter needs a transition sentence to the next

## China-Specific Considerations
- Always mention domestic alternatives: DeepSeek for LLM, Feishu/DingTalk for messaging
- Highlight cost and latency benefits of domestic options
- WSL2 note is important for Windows users in any dev tool article
