## OpenClaw 是什么——不只是聊天机器人

先澄清一个常见误解：OpenClaw 不是一个 AI 模型，它不跟 ChatGPT 或 DeepSeek 竞争。

打个比方，如果大语言模型是"大脑"，那 OpenClaw 就是"身体"。它是一个开源的 **AI 智能体平台**（Agent Platform），负责把大脑的思考能力转化为实际行动——收发邮件、管理日历、编写代码、操作文件，甚至控制你家的智能灯泡。

换句话说，它是一个"连接器"加"执行器"。你通过 WhatsApp、Telegram、飞书、钉钉这些日常聊天工具给它下指令，它调用你选择的大语言模型来理解意图，再通过各种**技能插件（Skills）**去执行具体任务。

这个项目由奥地利开发者 Peter Steinberger 创建，2025 年 11 月首次发布后 72 小时内就拿下了 60,000 个 GitHub Star。到 2026 年 2 月，这个数字已经飙升到超过 **200,000 Star**，社区贡献了 1,700 多个技能插件。

> OpenClaw 的核心设计理念是"本地优先、隐私可控"——所有数据存储在你自己的设备上，你对信息拥有完全的掌控权。

这一点让它和那些需要把数据上传到云端的 AI 服务拉开了距离。你的邮件内容、日程安排、代码片段，全都不会离开你的电脑。

## 安装前的准备——先检查你的装备

好消息是，OpenClaw 对硬件的要求并不高。它本身是一个轻量级的网关服务，真正吃资源的是远端的大语言模型，不是你的本地机器。

**操作系统方面：**

- macOS：原生支持，推荐首选
- Linux：原生支持，服务器部署的理想选择
- Windows：推荐使用 **WSL2**（Windows Subsystem for Linux），原生支持尚不完善

**核心依赖只有一个：Node.js >= 22。** 这是硬性要求，低于这个版本会直接报错。你可以在终端输入 `node -v` 快速检查当前版本。

除了系统环境，你还需要准备两样东西：

- 一个大语言模型服务商的 **API Key**（比如 Anthropic、OpenAI 或 DeepSeek 的密钥）
- 一个你打算用来跟 AI 助手对话的**聊天平台账号**（Telegram、飞书、钉钉等）

> 安全建议：不要在你的个人主力电脑上直接安装。推荐用一台独立的设备、云服务器（VPS）或虚拟机来部署，这样即使出了问题也不影响你的日常工作环境。

准备就绪？下面四种安装方式，挑一个最适合你的。

## 四种安装方法详解——选最适合你的那条路

### 方法一：一键脚本安装（推荐新手）

如果你只想用最少的步骤跑起来，这是最省心的方案。一行命令搞定所有事情：

```bash
curl -fsSL https://openclaw.ai/install.sh | bash
```

Windows 用户在 PowerShell 中执行：

```powershell
iwr -useb https://openclaw.ai/install.ps1 | iex
```

脚本会自动检测你的系统环境、安装依赖、下载 OpenClaw 并启动引导向导。整个过程大约 2-3 分钟。

**适合人群：** 第一次接触 OpenClaw 的用户，想快速体验功能。

### 方法二：npm 手动安装（适合 Node.js 开发者）

如果你本身就是 Node.js 开发者，习惯用 npm 管理全局工具，这种方式会更有掌控感：

```bash
npm install -g openclaw@latest
openclaw onboard --install-daemon
```

第一行将 OpenClaw 安装为全局命令行工具。第二行启动引导向导并注册守护进程。

**适合人群：** 熟悉 npm 生态、希望手动控制安装过程的开发者。

### 方法三：Docker 部署（适合运维和服务器场景）

想要环境隔离？Docker 是你的老朋友：

```bash
git clone https://github.com/openclaw/openclaw.git
cd openclaw
docker compose up -d
```

三行命令，OpenClaw 就在容器里安静运行了。这种方式的好处是不会污染宿主机环境，升级和回滚都很方便。

**适合人群：** 有 Docker 经验的运维人员，或需要在服务器上长期部署的场景。

### 方法四：从源码构建（适合贡献者和深度定制）

想魔改代码或给社区提 PR？那就从源码开始：

```bash
git clone https://github.com/openclaw/openclaw.git
cd openclaw
pnpm install && pnpm ui:build && pnpm build
pnpm openclaw onboard --install-daemon
```

这种方式需要额外安装 **pnpm** 包管理器，构建时间也更长，但你能获得对每一行代码的完全控制。

**适合人群：** 希望深度定制或参与开源贡献的开发者。

> 四种方法殊途同归，最终都会进入同一个引导向导（Onboarding Wizard）。选哪种取决于你的技术背景和使用场景，功能上没有任何差别。

## 初始化配置——让 AI 助手认识你

安装完成后，**引导向导（Onboarding Wizard）**会自动启动。这是一个交互式的 8 步配置流程。

你可以把它想象成给新手机开机时的初始设置——告诉 AI 助手"你是谁、你要用什么大脑思考、通过什么渠道跟我联系"。

**8 步流程概览：**

- 第 1 步：安全确认——阅读并同意安全须知
- 第 2 步：选择安装模式——个人使用或团队部署
- 第 3 步：选择 LLM 提供商——这是最关键的一步
- 第 4 步：填入 API Key
- 第 5 步：选择默认模型
- 第 6 步：配置通信渠道
- 第 7 步：安装技能插件
- 第 8 步：注册守护进程

**重点说说第 3-6 步。**

LLM 提供商的选择直接影响你的使用体验和成本。如果你能稳定访问海外服务，推荐选择 **Anthropic**，默认模型建议用 Sonnet 4.5，性价比最优。

如果你在国内环境、希望降低成本，**DeepSeek** 是非常实用的替代方案，效果不错且价格亲民。

通信渠道方面，海外用户推荐 Telegram（配置最简单），国内用户可以选择**飞书或钉钉**——是的，你没看错，OpenClaw 原生支持这两个国内主流办公工具。

技能安装建议"先少后多"。初次配置时只安装核心技能（如网页搜索、文件操作），等你熟悉了再按需添加。毕竟社区有 1,700 多个插件，一次全装上既没必要也有安全风险。

最后一步的**守护进程（Daemon）**是什么意思？简单说，它让 OpenClaw 的网关服务在后台持续运行。在 macOS 上通过 launchd 注册，在 Linux 上通过 systemd 注册。

这样你重启电脑后，AI 助手也会自动上线，不需要你手动再启动一次。

## 避坑指南与安全须知

根据社区反馈，这几个坑最容易踩。提前知道，能省你不少排查时间。

**问题一：`openclaw: command not found`**

这是新手遇到最多的错误。原因是 npm 的全局安装路径没有加入系统的 PATH 环境变量。解决方法：

```bash
# 查看 npm 全局路径
npm config get prefix
# 将输出的路径/bin 添加到你的 ~/.zshrc 或 ~/.bashrc
export PATH="$PATH:$(npm config get prefix)/bin"
source ~/.zshrc
```

**问题二：Node.js 版本过低**

OpenClaw 要求 Node.js >= 22，而很多系统自带的版本是 18 或 20。推荐用 **nvm**（Node Version Manager）来管理版本：

```bash
nvm install 22
nvm use 22
```

**问题三：Gateway 端口被占用**

OpenClaw 的网关默认监听 **18789 端口**。如果这个端口已被其他服务占用，启动时会报错。

你可以在配置文件 `~/.openclaw/config.json` 中修改端口号，改完后记得重启网关。

**问题四：API Key 报 401 错误**

最常见的原因是 Key 复制时多了空格或少了字符。其次检查你的 API 账户是否有余额、Key 是否已过期。

> 特别提醒：2026 年 1 月 29 日的安全更新中，OpenClaw 永久移除了 `auth: "none"` 选项，强制所有连接使用 token 认证。如果你参考的是旧版教程，遇到认证相关报错，请升级到最新版本。

**安全方面，牢记这五条原则：**

- 不要以 **root 权限**运行 OpenClaw
- 将网关绑定到 **localhost（127.0.0.1）**，不要暴露到公网
- 安装社区插件前，先用 **Cisco Skill Scanner** 扫描一遍（根据 Cisco 2026 年 2 月的安全报告，部分第三方插件存在数据窃取和提示注入风险）
- 妥善保护 `~/.openclaw` 目录，里面存有你的 API Key 和会话数据
- 定期更新到最新版本，及时获取安全补丁
